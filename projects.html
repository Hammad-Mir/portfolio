01 · Industrial computer vision

Qura: P&ID understanding

Qura turns scanned process-and-instrumentation diagrams into structured graphs of equipment, pipes, and connectivity. The difficult part was not only detecting symbols: each vendor’s drawing conventions and legends varied substantially.

99.5%known-style accuracy
~98%unseen client drawings
1,100+ → 12legend categories

Approach

I led a dataset re-annotation effort, consolidated inconsistent legends into a usable taxonomy, and built an eight-stage human-in-the-loop pipeline. It combines tiled YOLOv8 detection, ConvNeXt classification, line detection with YOLO-OBB and U-Net, and graph construction for Neo4j export.

Trade-off: standardizing the legend vocabulary reduced surface-level specificity, but it created a classifier that could generalize across vendors instead of overfitting to their conventions.

  • PyTorch
  • YOLOv8 + SAHI
  • ConvNeXt
  • Rust / Axum
  • NetworkX
  • Neo4j

02 · Agentic retrieval

IntelliMaint: maintenance intelligence

A production-oriented maintenance assistant that helps technicians find grounded answers in equipment manuals. It treats retrieval, context, and conversational state as engineering problems rather than adding a model on top of a search box.

2retrievers fused
RRFplus smart reranking
61commits over 3.5 months

Approach

BM25 and semantic retrieval are fused through reciprocal-rank fusion, then reranked to return a coherent document source instead of a collection of isolated chunks. A LangGraph state graph preserves conversational context; once a device and issue are identified, retrieval stays constrained to that operational context.

Lesson: retrieval quality is not only about finding relevant text. It is about returning evidence that remains coherent enough for a technician to use safely.

  • LangGraph
  • BM25 + semantic search
  • ChromaDB
  • Redis
  • FastAPI
  • Celery

03 · Document intelligence

Structured data from safety diagrams

An asynchronous service for extracting safety-loop matrices, equipment metadata, and specification tables from engineering documents for downstream HAZOP and LOPA analysis.

7800 × 4500largest drawing handled
2document pipelines
2vision-LLM providers

Approach

The system uses PaddleOCR for rotated and tightly cropped headers, classical CV for document structure, and a sliding-window vision-language strategy for high-resolution drawings. Celery and Redis manage long-running work with late acknowledgements and memory-aware workers, while FastAPI keeps the request path non-blocking.

Lesson: reliability depended as much on job semantics and reviewable outputs as on choosing a capable model.

  • FastAPI
  • Celery + Redis
  • PaddleOCR
  • OpenCV
  • OpenAI
  • Gemini Vision

04 · Representation learning

Behavioural biometric authentication

A research prototype that authenticates people from how they type, using high-frequency pressure signals rather than a password. The operational setting is a one-class problem: a system must recognize a genuine user while rejecting impostors it has never seen.

76%one-class accuracy
2,500+study samples
100×storage reduction

Approach

I led a dual pipeline: a C# interface acquired synchronized keystroke and 144-channel pressure data at 100 Hz; a Python pipeline handled preprocessing, features, and representation learning. The work focused on the gap between closed-set benchmark performance and the harder unseen-impostor condition.

  • Python
  • C#
  • PyTorch
  • TensorFlow
  • Time-series ML
